# GAL 1.0 / GAL 2.0 Implementation-to-Theory Audit

**Audit type:** source-level conceptual audit  
**Audited branches:** research/gal-native-reproduction and research/gal-2.0-core  
**Purpose:** identify which parts of the shared framework are currently represented in code, which are proxies, and which remain unimplemented. This is not an empirical evaluation or a code-security audit.

## 1. Executive finding

The two branches operationalise different parts of the generational-information problem.

- GAL 1.0 has an explicit agent/environment interaction loop and several distinct inheritance mechanisms. Its present foundational environment is a fixed symbolic task world with stochastic task outcomes.
- GAL 2.0 has richer typed records for evidence, capabilities, provenance, memory kinds, and successor verification. Its task outcome is generated by a synthetic probability function, and the executor does not use stored memories or procedures to solve tasks.
- Neither implementation currently realises the full shared stochastic-kernel model in GAL_RESEARCH_PROGRAMME_FRAMEWORK.md.
- Neither implementation, as audited here, establishes a general theorem that inheritance improves adaptation.

### GAL 1.0 mechanism details

- A: no inheritance operation.
- B-copy: copies parent concepts and skill values.
- C-full: copies concepts and uses stochastic iterative teaching updates for positive parent skill values.
- C-no-memory: uses the teaching update but does not copy concepts.
- C-low-effort: copies concepts and uses a one-iteration, lower-correction teaching path.

The task mechanism uses concepts: a matching associated concept halves task difficulty. Independently acquired concepts are sampled from a broad numeric vocabulary, while the environment rewards five specific concept identifiers. This creates a defined chance of acquiring task-relevant concepts, not open-ended semantic concept discovery.

The inspected environment has a fixed task set. Claims about environmental volatility, phase boundaries, or adaptation under changing environments must be tied to the separate experiments that actually implement and test those conditions, not inferred from this foundational environment alone.

### GAL 1.0 metric caution

GenerationalKnowledgeAccumulation computes the average per-generation change between the first and last supplied knowledge scores. It is a descriptive slope over the supplied scalar metric. It is not, by itself, Shannon information, semantic knowledge, causal inheritance value, or a measure of epistemic reliability.

| Resource cost (C_g) | No full cost model | Not operationalised |
| Environmental shift | Context labels include “shifted”; transfer heuristic sees labels, but task success formula itself does not model a context-dependent causal change | Labels alone do not establish a real distribution shift |
| Memory utility | Memory is recorded and transferred | Executor does not consult memory, prerequisites, or procedures when attempting tasks |

### GAL 2.0 statistical interpretation

Capability proficiency is the empirical mean of recorded binary successes. The confidence field is a monotonic sample-count heuristic (n/(n+10)), not a posterior probability or calibrated confidence interval. The Wilson lower bound is used in a holdout verification gate; passing that gate establishes performance against the selected synthetic holdout tasks, not truth of a general semantic claim.

The Bayesian formalisation in gal2/ANALYTICAL_THEORY.md is currently a separate analytical model. The current Capability and Evidence implementation does not implement Bayesian likelihood updates or the linear opinion-pool inheritance equation. Any claim that the code implements that Bayesian theory would therefore be premature.

## 4. Cross-programme gaps

The following gaps matter before a common theorem can be mapped onto both codebases:

1. **Common outcome scale:** define a comparable loss and task distribution before comparing scores between programmes.
2. **Environment change:** specify a transition law for environments and a measurable shift quantity; context names alone are insufficient.
3. **Evidence dependence:** track shared ancestry and reused observations to prevent double-counting correlated evidence.
4. **Resource accounting:** measure learning, memory, teaching, verification, and transfer costs separately.
5. **Mechanism-to-outcome bridge:** specify how transmitted state changes recipient decisions and expected loss.
6. **Population effects:** distinguish individual lineage gains from population-level diversity, extinction, and selection effects.
7. **Operational theorem mapping:** every formal variable must map to a code variable or remain explicitly theoretical.

## 5. Priority research tasks

### Priority 1 — Define a common mathematical outcome

Choose a bounded loss that both programmes can instantiate without pretending their native task spaces are identical. A task-family-specific mapping may be needed. Report raw domain-specific outcomes as well as any normalised common outcome.

### Priority 2 — Derive a mechanism-specific inheritance result

Start with the native GAL 1.0 inheritance operators and derive their expected successor state under stated assumptions. Separately derive the GAL 2.0 evidence-gated transfer operator. Do not assume the operators are equivalent.

### Priority 3 — Model stale and correlated information

Derive counterexamples where inherited information harms a successor because the environment changed, parent evidence is noisy, or the same evidence is counted repeatedly through multiple generations.

### Priority 4 — Add explicit cost and population terms

A claim of net advantage must include the resource cost of acquiring, retaining, transmitting, and validating information. Population-level claims additionally require an explicit population transition model.

### Priority 5 — Empirical design only after model audit

Any subsequent experiment should be preregistered with matched exposure, explicit baselines, sufficient independent seeds or lineages, a primary estimand, uncertainty intervals, and immutable raw artifacts. No experiment should be described as validating a theorem unless its assumptions are checked against the implementation and data-generating process.

## 6. Audit conclusion

GAL 1.0 currently offers the more direct native artificial-life mechanism testbed. GAL 2.0 currently offers the more explicit knowledge/evidence/provenance data model. They are complementary research programmes, not interchangeable implementations.

The strongest shared research opportunity is to derive and test a mechanism-specific theory of when generational transfer reduces recipient loss after accounting for evidence reliability, environmental change, dependence, and resource cost. The current code provides useful components, but the bridge from formal information transfer to general adaptive benefit remains an open research problem.
